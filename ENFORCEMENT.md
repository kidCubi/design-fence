## Enforcement ledger

Which rules a command actually enforces, and which depend on an agent or a person choosing to follow them. A project copies this to `.agents/ENFORCEMENT.md` and adds its own rows.

- **enforced**: breaking the rule makes a command fail or a hook refuse. The row names it.
- **advisory**: everything else, including what a tool detects and only warns about.

The last column matters most: a green check is easily read as "this complies" when it only means that the thing it measures passed.

| Rule | Status | By | What a green result does not mean |
|---|---|---|---|
| The project's checks pass on what changed | enforced | pre-commit hook → `design-fence check`; pre-push hook again; CI | That files the checks' `when` patterns do not match were checked. The hook checks the working tree, so what is committed may differ from what passed when only part of it is staged. |
| A commit that changes code carries the reflect review's verdict (`Reflect:` line) | enforced | commit-msg hook; pre-push hook and CI on every pushed commit | That the review ran, or was thorough: the line is the author's word. Merge commits are not checked. |
| The git hooks are on in every clone | advisory | `install.mjs` sets `core.hooksPath`; `design-fence rules` says when they are off; CI catches what they missed | — |
| Never skip the hooks (`--no-verify`) | enforced in Claude Code, Codex, OpenCode and GitHub Copilot's CLI (in a trusted folder); advisory elsewhere | the agent hooks (`design-fence agent-hook` in the project, and the plugin, which carries its own copy): `--no-verify`, `commit -n`, `-c core.hooksPath=…`, changing `core.hooksPath`, running the hooks by hand; CI reports what a skipped hook would have refused | That the hooks ran: a person can turn them off (`disableAllHooks`, Codex's `[features] hooks`, removing the plugin), Codex runs them only once trusted (`/hooks`, again after each update), and a command they cannot read (a script, an alias, `GIT_CONFIG_*` variables) gets through |
| design-fence's own files, and the hooks, change only with the human's word | enforced in Claude Code, Codex, OpenCode and GitHub Copilot's CLI (in a trusted folder) with the plugin; advisory elsewhere | the plugin (`harness/`), outside the repository: edits and shell writes to design-fence's folder, `.agents/validate.json`, the hooks' settings in the project and in the person's tools, and turning the hooks or the plugin off, need the human (Claude Code asks; elsewhere "design-fence: allow" in their message, for that turn). It acts even once design-fence's folder is gone, while `AGENTS.md` has its block | That the files did not change: a script the agent wrote and then ran, an unparsed command, another tool, or a person removing the plugin get through. Only CI on a protected `main`, and managed settings, are out of the agent's reach |
| Read the playbook the work goes to, whole, before its first step | advisory | `install.mjs` writes design-fence's block into `AGENTS.md` and links the skills; `design-fence rules` says whether they are there | That an agent read the playbook: the block and the skills only put it in front of the agent |
| One design-tool screenshot per phase | enforced in Claude Code, Codex, OpenCode and GitHub Copilot's CLI (in a trusted folder); advisory elsewhere | the agent hooks: the second screenshot refused until the human writes again (the phase's end) | That the one taken was at the phase's end, or of the right frame. A screenshot that failed still counts. A tool not named for Figma is not counted |
| design-fence's `figma/` scripts run with `design-fence figma`, not pasted into `figma_execute` | enforced in Claude Code, Codex, OpenCode and GitHub Copilot's CLI (in a trusted folder); advisory elsewhere | the agent hooks, on `figma_execute` and `use_figma` | That the command was tried before falling back: a script pasted under another name gets through |
| The rules survive a compaction | enforced in Claude Code, Codex, OpenCode and GitHub Copilot's CLI (in a trusted folder) | the agent hooks give design-fence's block of `AGENTS.md` again after a compaction | That the agent follows them |
| Ground before writing (read the code and the catalog, never memory) | advisory | — | — |
| "Not found" is a finding, filed as an issue | advisory | — | — |
| Issues go to the tracker `AGENTS.md` names, or into the summary when it cannot be reached; never into a file or a tool it does not name | advisory | — | — |
| Name what ran in every report | advisory | — | — |
| End done or parked | advisory | — | — |
| Design module: nothing passes the design gate without the human's word | enforced in Claude Code, Codex, OpenCode and GitHub Copilot's CLI (in a trusted folder) for the record of it; advisory elsewhere | the agent hooks: an edit that marks a spec or a view's copy `approved` asks the human (Claude Code), or is refused until they write "design-fence: allow" (Codex, OpenCode) | That the human looked at the design before giving their word; an approval written through a script the hook cannot read, or in another tool; `approved_by`, which stays the author's word |
| Design module: no unbound value and no frame without auto-layout in Figma | advisory | `figma_lint_design` (design-system, layout, wcag) and `figma/lint-gaps.js`, run through the bridge (`playbooks/design.md`, step 3) | That the nodes not linted follow the rules, or the instances inside a node (linted with their own component); that what the lint does not know (effects, typography values outside a text style) is bound |
| Design module: the tokens file is the tokens export's | enforced, once a tokens export has run (`design/tokens.lock`); in the session, in Claude Code, Codex and OpenCode | pre-commit hook and CI → `design-fence design` (the file's hash against the export's record); the agent hooks ask the human before an edit of the tokens file or its record | That the file still matches Figma: a variable changed in Figma since the export is seen only by `design-fence figma tokens --hash-only` (through the bridge, by hand). An edit that also rewrites the record's hash |
| Design module: each spec's status has what it needs (Figma node and version, approver, story); built specs have their stories; `design/index.md` says what the specs say; `flows.yml` holds together (ids, actions between views that exist, flows whose steps follow, components the index lists) | enforced (the installer adds the check with the design module) | pre-commit hook and CI → `design-fence design` | That the stories match Figma (checked by values once, when built), that a story exists for each variant and state, that `approved_by` is true. Stories are not checked where Storybook's index is not built (the check says so); a library story with no spec is said, and refused only with `design.strict`. That `flows.yml` matches the routes in the code |
| Design module: no raw value in the library's CSS where a token belongs (a colour, a length, a time), and no token of a layer components do not bind (`design.tokens.private`) | enforced for the components whose spec is approved or built; said, not refused, for the others until `design.strict` | pre-commit hook and CI → `design-fence design` | Styles written outside `.css` files (in JavaScript, in a template); values in the app's code outside `design.library`; a line excused with `design-fence: raw` (its reason is the author's word); that the token bound is the right one for the part |
| Design module: the philosophy, the voice of the copy, behaviour, motion, and what a view's words say | advisory | — (`playbooks/reflect.md` asks; `design/content/` holds the approved words) | — |
